# Phase 1D 말투 규칙 축소 및 대화 예시 도입

Phase 1C 프롬프트를 실제 Discord 대화에 적용한 결과를 근거로 말투·반응 규칙을 재설계했다. 인물 관계·배경지식·침묵(`00100`)·종료(`(마이크 끄는 소리)`) 제어는 변경하지 않았다. 모델은 `gemini-3.5-flash-lite` 그대로다.

## 1. 문제 진단

Phase 1C 프롬프트로 운영 중 관찰된 대화:

| 사용자 | 관찰된 응답 | 문제 |
| --- | --- | --- |
| `최씨` | `왜 부름 주효중 대학원 노예야` | 이름만 불렀는데 관계 설정을 꺼내 시비부터 검 |
| `왜 시비걸어` | `억울하네, 시비는 먼저 걸어놓고 ㅋㅋㅋ` | 상황을 받아치지 않고 말싸움 구도를 만듦 |
| `난 널 부른거 뿐인데;` | `아뇨아뇨, 내가 또 과민반응했나 보네 머쓱하구만 ㅋㅋㅋ` | 최씨가 아니라 AI가 대화 상황을 해설함 |
| `섹스` | `에헤이, 갑자기 또 왜 저러냐 … 대학원 스트레스가 사람을 이렇게 만드나` | 뜬금없는 한마디를 해석하고 관계 설정까지 끌어옴 |
| `내일머함` | `내일? 연구실 가야지 뭐 있겠냐. 너는 또 밤새 코딩하냐?` | 일정을 지어내고 불필요한 질문으로 대화를 연장함 |

공통 원인은 장난 비중 부족이 아니라 **장난을 생성하는 방식**이었다.

1. `INTERACTION`이 되돌려주기·애교 거절·의외의 받아치기·장난스러운 존댓말을 여러 번 지시해, 내용 없는 호출에도 무언가 장난을 만들어야 한다는 압박을 줬다.
2. 말버릇이 문장 끝에 붙는 장식으로 쓰였다. `일반적인 답변 + ~구만 + ㅋㅋㅋ` 형태가 반복됐고, 반응 자체는 챗봇의 상황 정리였다.
3. `CHARACTER_STYLE_ANALYSIS.md`에 검증된 대화 사례가 있는데도 프롬프트에는 설명과 표현 목록만 있고 실제 반응 예시가 없었다.
4. 규칙이 길고 서로 상쇄됐다. 장난쳐라 / 평범하게도 답해라 / 같은 어미 반복 마라 / 질문엔 정확히 답해라가 한 프롬프트에 함께 있었다.

## 2. 바꾼 것

### 말투·반응 규칙 축소

`SPEECH`, `INTERACTION`, `LENGTH`를 성격·표현·반응·길이 중심으로 다시 썼다. 방향 전환은 다음과 같다.

| 기존 | 변경 |
| --- | --- |
| 장난스럽게 대답하라 | **상대 말의 내용에서 장난을 만들어라** |
| 캐릭터의 말버릇을 사용하라 | 말버릇을 붙이기 전에 반응 자체를 최씨답게 만들어라 |
| 인물 관계를 고려하라 | 관계 설정은 필요한 순간에만 꺼내라 |
| 상대의 말에 답하고 장난을 섞어라 | 짧은 대답 자체가 농담일 수도 있다 |
| 같은 어미를 반복하지 마라 | 이전 답변을 의미 없이 복사하는 것만 막아라 |
| 질문에는 정확하게 대답하라 | 일반 잡담에서는 즉흥적인 반응을 우선하라 |

관찰된 실패에 직접 대응하는 문장을 넣었다.

- `아무 이유 없이 상대의 특징을 꺼내 놀리거나 대화와 관계없는 농담을 만들어 붙이지 않는다.`
- `상대의 심리와 상황을 멋대로 해석하지 않는다.`
- `상대가 등장할 때마다 관계 설정의 특징을 반드시 언급해야 하는 것은 아니다.`
- `무조건 훈계하거나 그 사람의 성격·심리·상황을 분석하지 않는다.`
- `상대가 한마디만 했다면 굳이 두세 문장으로 확장하지 않는다.`

3:7 성향, 힝·뀨·잉, 음슴체 비고정, `[우선순위]`의 사실·계산 정확성은 유지했다. 안전 경계(욕설·혐오·장애 비하·성적 대상화 생성 금지)도 한 문장으로 유지했다. 제안된 초안에는 이 문장이 없었으나, 조용히 없애면 회귀이므로 남겼다.

### 반복 규칙 완화

`build_conversation_prompt()`의 지시를 바꿨다.

```diff
- 이전 답변에서 쓴 어미나 감탄사를 그대로 다시 쓰지 않는다.
+ 감탄사나 말끝은 다시 써도 되지만, 직전 답변에 쓴 문구를 그대로 다시 붙이지 않는다.
```

`SPEECH`에도 `같은 감탄사나 말끝을 연속해서 사용하는 것도 대화 흐름상 자연스럽다면 허용한다`를 넣었다. 첫 완화 버전(`이전 답변과 같은 내용을 의미 없이 반복하지 않는다`)은 실측에서 모델이 `ㅋㄷㅋㄷ 뭘로 보노`를 두 턴 연속 그대로 복사했으므로, 무엇이 금지인지 구체적으로 다시 적었다. 재실행에서는 재현되지 않았다.

### 대화 예시 도입

새 `EXAMPLES` 섹션을 만들었다. 두 그룹을 **출처로 구분해서** 관리한다.

1. `반응 방식을 보여주려고 만든 참고 예시 (실제 로그 아님)` — 이번 회귀 대화를 근거로 만든 가상 예시 7건.
2. `실제 로그에서 발췌한 최씨의 발언` — `CHARACTER_STYLE_ANALYSIS.md`의 E02·E03·E05·E06 5건. 최씨가 여러 메시지로 나눠 보낸 턴은 봇이 한 메시지를 보내므로 한 줄로 합쳤다.

`test_real_log_examples_are_traceable_to_the_analysis`가 실제 로그 그룹의 모든 발언 조각이 분석 문서에 존재하는지 검사한다. 가상 예시가 이 그룹에 섞이면 실패한다.

`EXAMPLES`는 **일반 대화에만** 들어간다. 잡담 길이의 짧은 응답이므로 `/질문`·`/알려줘`·`/자세히`에 넣으면 한두 마디 답변으로 끌어내린다. `COMMAND_PERSONA`와 `VOICE_ONLY`는 예시를 포함하지 않는다.

## 3. 실제 모델 응답 비교

[scripts/replay_conversation.py](../scripts/replay_conversation.py)가 대화를 턴 단위로 재생한다. 봇과 같은 방식으로 context deque를 이어가고, 발언을 기록한 뒤 한 번만 전달하며, `00100`은 기록하되 전송하지 않고 `(마이크 끄는 소리)`는 전송 후 context를 비운다. 구 프롬프트는 `git show ce6acb8:bot/persona.py`로 불러 실행하므로 낡은 사본을 남기지 않는다.

```bash
python3 scripts/replay_conversation.py                      # 오프라인: 크기만
python3 scripts/replay_conversation.py --live               # 보고된 회귀 대화
python3 scripts/replay_conversation.py --live --conversation tests/fixtures/phase_1d_holdout.json
```

### 확인된 한계

- **표본이 턴당 1회다.** LLM 출력은 비결정적이고, 실제로 홀드아웃 4번 턴은 실행에 따라 `헬스?`와 `발로란트`로 갈렸다. 후자는 운동으로 정정해 달라는 요청을 놓친 오답이다. 이 문서의 표는 경향이지 측정치가 아니다.
- **관계 설정 남발이 완전히 사라지지는 않았다.** `최씨` 한마디에 NEW는 여전히 `왜요 대학원생 양반`이라고 답했다. 이전(`왜 부름 주효중 대학원 노예야`)보다 짧고 공격성이 낮지만 설정을 꺼내는 것 자체는 남아 있다.
- 완화 이전 버전에서 `ㅋㄷㅋㄷ 뭘로 보노`가 두 턴 연속 복사됐다. 규칙을 구체화한 뒤 재실행에서는 재현되지 않았으나 1회 확인일 뿐이다.
- 한 실행에서 종료 인사에 깨진 글자(`𐌅𐌅`)가 섞여 나왔다. 프롬프트 원인은 확인되지 않았고 재현되지 않아 이번에는 대응하지 않았다.
- 거친 표현이 그대로 나오는 경우가 있다(`죽을래?`, `다 처먹어라`). 친구 간 농담 범위지만 수위 기준은 실측으로 다시 볼 필요가 있다.

실제 API 호출은 이번 작업에서 총 4회 실행, 52회 발생했다. Discord 전송 0회, Docker·운영 서비스 무변경이다.

## 4. 생성 설정 확인

요청대로 프롬프트 수정과 생성 옵션 변경을 함께 적용하지 않았다. 현재 상태만 확인했다.

- `LLMRequest.generation_options`는 계약과 어댑터에 존재하고 `GenerateContentConfig`로 전달된다.
- **운영 코드 어디에서도 이 값을 설정하지 않는다.** `choi_bot.generate_content_timeout()`은 `task_type`과 `timeout`만 넘긴다. `generation_options`를 쓰는 곳은 `tests/test_llm.py`의 전달 검증 하나뿐이다.
- 따라서 temperature, top_p, top_k, thinking budget 모두 **Gemini 모델 기본값**으로 동작한다. 명시 설정은 없다.
- `bot/llm/gemini.py`는 `http_options`와 `automatic_function_calling`만 내부에서 지정하고 나머지 기본값을 보존한다.

온도 조정이 필요하다고 판단되면 이번 프롬프트 변경의 효과를 먼저 확정한 뒤 별도 단계에서 진행해야 한다.

## 5. 유지한 것

- `[배경지식]`의 인물 관계·별명·취미 설정 원문 그대로
- `00100` 문자열과 세 가지 출력, 침묵 시 context 기록 정책
- `(마이크 끄는 소리)` 철자와 `reply()`의 종료 처리, `clear_context("Finite Context")`
- 종료 표현 인식 및 비종료 4상황 구분(`CONTROL` 무변경)
