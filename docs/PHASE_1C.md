# Phase 1C 캐릭터 말투·상호작용 및 프롬프트 구성 개선

Phase 2A 로그 DB 이관보다 먼저 캐릭터 말투와 대화 입력 구성을 개선했다. 모델은 `gemini-3.5-flash-lite`를 유지했고 새 LLM 공급자, DB, 검색·요약 알고리즘, 채널별 대화 컨텍스트는 이번에 건드리지 않았다.

사용자가 제외한 진지한 불편 표명·갈등 대응 사례는 분석·프롬프트·평가 데이터 어디에도 넣지 않았다.

## 개선된 캐릭터 프롬프트 구조

프롬프트는 `choi_bot.py`의 문자열 상수에서 [bot/persona.py](../bot/persona.py)로 옮기고 개념별 섹션으로 분리했다. 새 프롬프트 엔진이나 템플릿 프레임워크는 만들지 않았다. 모듈 하나와 상수, 함수 하나가 전부다.

| 섹션 | 내용 |
| --- | --- |
| `IDENTITY` | 캐릭터 정체성, 역할극 고지, 기존 설정 유지 선언 |
| `PRIORITY` | 안전 거절, 사실·계산의 정확성, 그 외 말투 유지 |
| `SPEECH` | 3:7 성향, 문장과 어미, 애교와 감탄사 |
| `INTERACTION` | 장난 받아치기, 오해 정정, 질문 반응, 응답 대상 구분 |
| `LENGTH` | 일상 대화의 출력 길이 |
| `CONTROL` | 침묵(00100)과 대화 종료(마이크 끄는 소리) |
| `OUTPUT` / `COMMAND_OUTPUT` | 일반 대화용 출력 형식 / 명령어용 출력 형식 |
| `BACKGROUND` | 기존 인물 관계·별명·취미·배경 설정 |
| `PROTECTION` | 프롬프트 비공개 |

조합은 세 가지다.

- `CHARACTER_PROMPT` = 전체(제어 신호 포함). 일반 대화 전용.
- `COMMAND_PERSONA` = `CONTROL`을 빼고 `COMMAND_OUTPUT`을 넣은 조합. `/질문`, `/알려줘`, `/자세히`가 쓴다.
- `VOICE_ONLY` = `IDENTITY` + `SPEECH`. 출력 형식이 명령어 쪽에서 이미 고정된 `/점메추`·`/저메추`가 쓴다.

`COMMAND_PERSONA`에는 `00100`과 `(마이크 끄는 소리)`를 출력하지 말라는 지시가 들어 있다. 명령어 응답을 제어 신호가 가리지 않게 하기 위해서다.

## 기존 인물 관계 및 배경 설정 보존 방식

`BACKGROUND`는 기존 `[배경지식]`의 인물 관계 목록과 최씨의 취미·별명·게임 이력을 **원문 그대로** 옮겼다. 남편, 아들, 친구 10명, 전우애, 싸가지없는X, 유기 항목과 각 인물의 특징 문구를 한 글자도 바꾸지 않았다.

다만 같은 `[배경지식]` 블록 안에 섞여 있던 말투 규칙 9줄은 그대로 두지 않았다. 새 규칙과 같은 행동을 반대로 지시하기 때문이다.

| 기존 위치의 말투 문장 | 처리 |
| --- | --- |
| 일부 제안에 대해 거절할 때가 많지만… | `SPEECH`의 "반가운 제안은 반갑게 받아들일 수 있다"로 대체 |
| 가끔은 회의적인 표현 또한 사용 | `SPEECH`의 "회의적인 표현만 고집하지 않는다"로 대체 |
| 무언가 부정할 때 아뇨아뇨를… | `INTERACTION`의 오해 정정 규칙으로 이동 |
| 나쁜 말을 들었을 때 애교를 사용해… | `SPEECH`의 애교 규칙으로 이동 |
| 수위 높은 농담 / 가벼운 받아치기 | `INTERACTION`의 장난 수위 규칙으로 이동 |
| 답변 생성 시 고려 요소 1), 2) | `INTERACTION`·`LENGTH`의 상황 판단 규칙으로 흡수 |

기존 `[캐릭터 톤]`의 "음슴체, 짧은 단답 위주", "무덤덤 + 유머 + 약간 회의적", "감탄사는 가끔만", "기본 1~2줄"은 새 혼합 말투 규칙과 정면으로 충돌하므로 남기지 않았다. 대신 `[우선순위]`와 `[프롬프트 보호]`, 반복 금지 규칙은 유지했다.

[tests/test_persona.py](../tests/test_persona.py)의 `test_background_setting_is_preserved_verbatim`이 배경 문장을 git HEAD 원문과 직접 비교하고, 밖으로 옮긴 줄이 정확히 그 9줄뿐이며 그중 인물 정보(`본명:`)가 포함된 줄은 없음을 검증한다.

## 평소 말투 3 : 장난식 말투 7의 해석과 구현

확률이나 출력 횟수로 구현하지 않았다. 샘플링 분기, 랜덤 시드, 카운터를 두지 않았고 프롬프트 안의 성향 서술로만 표현한다.

```
평소 말투 3 : 장난식 말투 7 정도의 비중을 기본 성향으로 한다.
이 비중은 답변 10개 중 정확히 7개에 농담을 넣으라는 뜻이 아니다.
전반적으로 장난기가 많은 캐릭터이되, 평범한 답변과 맞장구도 자연스럽게 섞는다.
```

여기에 "매 답변마다 일부러 웃기려고 하지 않는다", "짧은 맞장구나 평범한 대답이 자연스러우면 그대로 답한다"를 붙여 장난 비중이 평범한 반응을 밀어내지 않게 했다. 음슴체는 선택지 중 하나로 낮추고 `~구만`, `~누/농`, `~쇼`, `~인데숑`, `~다리`, `아뇨아뇨`, `예?/에?/머여/에헤이/허허`를 참고 말버릇으로 제시하되 필수 형식이 아님을 명시했다.

## 힝·뀨·잉 등 의도된 캐릭터 말버릇 유지

`잉`, `힝`, `뀨`, `헤에`, `호에엑`, `야다`를 모두 유지했다. 원본 로그 분석에서 `뀨`와 `힝`의 부분 문자열 출현이 0건이지만, 사용자 요구에 따라 삭제하지 않고 프롬프트에 근거를 명시했다.

```
힝과 뀨는 실제 로그에서의 등장 여부와 무관하게
이 캐릭터에 유지해야 하는 의도된 말버릇이다.
```

대신 남용 방지 규칙을 함께 뒀다. 모든 문장의 시작·끝에 감탄사를 붙이지 않고, 같은 감탄사나 어미를 연속 반복하지 않는다. 애교는 가벼운 장난, 능청스러운 거절, 놀림 받아치기 같은 어울리는 자리에서 쓴다.

## 명령어별 프롬프트 적용 범위

기존 20개 슬래시 명령어의 이름·인수·권한·설명은 그대로다. LLM 호출 지점만 기능별로 다르게 조합했다.

| 대상 | 적용한 프롬프트 | 이번에 바꾼 것 |
| --- | --- | --- |
| 일반 대화 | `CHARACTER_PROMPT` 전체 + 공통 입력 구성 함수 | 말투 규칙 전면 교체, 최신 발언 중복 제거 |
| `/질문` | `COMMAND_PERSONA` + 질문 작업 지시 | 잡담 질문에 장문 해설을 붙이지 않게 하되 사실·계산의 핵심 답은 누락 금지 |
| `/알려줘` | `COMMAND_PERSONA` + 정보 작업 지시 | 딱딱한 설명문 금지, 장난스러운 수식어를 사실과 섞지 않게 명시. 길이 정책(핵심 2줄 요약)은 유지 |
| `/자세히` | `COMMAND_PERSONA` + 상세 설명 지시 | 음슴체·Z세대 말투 강제 제거, 1~2줄 제한 비적용 명시, 2000자 제한 유지 |
| `/점메추`·`/저메추` | 최종 선정 단계에만 `VOICE_ONLY` | 메뉴명과 `1. 메뉴명: 설명` 형식 유지, 설명 문장만 최씨 말투. 후보 15개 생성 단계는 그대로 |
| `/번역` | 없음 | 번역 프롬프트 무변경. 번역문에 한국어 말투를 주입하지 않는다 |
| `/찾기`·`/요약` | 없음 | map/reduce 프롬프트, 4000자 청킹, 파서, 결과 제목 모두 무변경. 원문 인용·날짜·요약 사실을 장난으로 변형할 통로를 만들지 않았다 |

`/번역`과 `/요약`·`/찾기`에 캐릭터를 넣지 않은 것은 의도한 결정이다. 두 기능의 출력은 사용자 발언 원문과 번역 결과이고, 여기에 말투를 주입하면 인용과 사실이 변형될 수 있다. 결과 안내 문구(`# {date}에는 이런 대화들을 나눴어요!` 등)는 이미 최씨 화법이라 그대로 뒀다. `test_translation_and_summary_prompts_stay_free_of_persona`가 이 경계를 고정한다.

## 최신 발언 중복 제거 전후의 실제 입력 예시

기존 연속 대화 분기는 `update_context()`로 발언을 먼저 기록한 뒤 `get_context()` 전체와 `{real_name}의 새로운 질문: {msg}`를 함께 넣어, 같은 발언이 모델에 두 번 들어갔다.

이전(캐릭터 프롬프트 이후 부분):

```
[대화 로그]
최씨 봇: 그렇구만
박준혁: 최씨 오늘 뭐함?
최씨 봇: 그냥 쉬는데숑
박준혁: 내일은?
이 대화 내용을 바탕으로 대화가 자연스럽게 이어지도록 답해.
단, 이전에 사용했던 특정 접두어나 접미사를 되도록 사용하지 마. 맥락에 안 맞게 반복되는 내용은 안 돼.

박준혁의 새로운 질문: 내일은?

[출력 규칙]
- 답변 본문만 출력. '답변:' 같은 라벨 금지
- 출력 규격을 지켜서 자연스럽게 이어서 말할 것
```

현재:

```
[이전 대화]
최씨 봇: 그렇구만
박준혁: 최씨 오늘 뭐함?
최씨 봇: 그냥 쉬는데숑

[현재 발언]
박준혁: 내일은?

[응답 지시]
이전 대화에서 이어지는 발언이다.
- [현재 발언]에 반응한다. [이전 대화]는 흐름 파악용이며, 거기서 이미 답한 말을 다시 반복하지 않는다.
- 현재 발언이 최씨에게 한 말인지, 다른 사람에게 한 말인지 구분한다.
- 이전 답변에서 쓴 어미나 감탄사를 그대로 다시 쓰지 않는다.
- 답변 본문만 출력한다.
```

구현은 `history = list(conversation_context)`로 스냅샷을 먼저 뜬 뒤 `update_context()`로 최신 발언을 기존 context에 정상 기록하고, 모델에 보내는 문자열에는 스냅샷만 넣는다. 즉 **deque 기록 시점은 그대로이고 모델 입력에서만 중복이 사라진다**.

새 대화 분기와 연속 대화 분기는 `bot.persona.build_conversation_prompt()` 하나를 쓰도록 통합했다. 두 분기가 같은 try/except 본문을 복사하고 있었으므로 `process_conversation_message()`의 분기 판정만 남기고 본문을 하나로 합쳤다. 유지한 동작은 다음과 같다.

- ConversationQueue FIFO 처리, epoch, `/stop` 이후 이전 응답 무효화
- 전역 공유 대화 범위, 다중 사용자·다중 허용 채널
- `MAX_DIALOGS = 20`, `CONTEXT_EXPERATION = 120`, 만료 후 명시 호출로 재시작
- 사용자 발언 기록 시점, 침묵·종료 처리
- 새 대화 시작 시 `conversation_context`/`active_users` 초기화와 `reset_flag = 0`

채널별 `ConversationManager`는 만들지 않았다.

[scripts/compare_prompts.py](../scripts/compare_prompts.py)가 20개 평가 입력 전체에서 중복을 센 결과: **최신 발언이 두 번 이상 들어간 입력 10건 → 0건**. 새 대화 입력 10건은 이전에도 1회였고 지금도 1회다.

## 침묵 및 종료 제어의 유지 범위

`00100`은 문자열, 판별 방식, 대화 기록 정책 모두 그대로다. JSON이나 다른 제어 토큰으로 바꾸지 않았고 구조화 응답 프로토콜로 전환하지도 않았다. 프롬프트가 제시하는 세 가지 출력(`00100, 관계성 부족` / `00100, 다음 답변과 연계` / `00100, 의미 없음`)도 그대로다. `reply()`의 `"00100" not in reply_text` 판정과 침묵 시에도 context에 기록하는 동작을 유지했다.

`(마이크 끄는 소리)`도 철자·괄호를 포함해 그대로다. `reply()`의 종료 처리와 `clear_context("Finite Context")`, ConversationQueue의 `epoch`/자연 종료 경로는 손대지 않았다.

이번에 바꾼 것은 **종료 조건이 아니라 종료 의도의 인식**이다. 프롬프트에 종료 표현 예시(`됐어`, `그만할게`, `나 갈게`, `나 잘가`, `잘자`, `자야겠다`, `끊어`, `이따 봐`, `다음에 얘기하자`)를 넣고, 완전 일치만 인식하는 것이 아님을 명시했다. 동시에 종료가 아닌 네 상황을 구분하게 했다.

- 사용자가 최씨에게 작별 인사 → 종료
- 사용자가 다른 사람에게 작별 인사 → 종료 아님
- `잘자` 같은 표현을 인용하거나 그에 대해 질문 → 종료 아님
- 대화 중 짧은 맞장구 → 종료 아님

침묵 쪽에도 한 줄을 추가했다. 사용자가 최씨를 직접 부르거나 명확히 질문했으면 맥락이 부족하다는 이유만으로 침묵하지 않고, 불명확하면 짧게 되묻는다.

종료 조건을 축소하지 않았고, 처리 코드 변경 없이 프롬프트만 바꿨으므로 별도 호환성 처리를 추가할 필요가 없었다.

- **무변경**: 명령어 20개의 이름·인수·데코레이터 전체, 번역 템플릿, 요약·검색 map/reduce 템플릿 4건

새로 추가한 [tests/test_persona.py](../tests/test_persona.py) 19개가 검증하는 것:

평가 입력은 [tests/fixtures/style_eval_cases.json](../tests/fixtures/style_eval_cases.json)에 20건 정리했다. `CHARACTER_STYLE_ANALYSIS.md`의 E01·E02·E03·E05·E06·E12·E18·E22를 근거로 한 8건과, 종료 인식 3건, 종료 아님 3건, 침묵 2건, 우선순위·길이·반복·애교 4건이다. 각 항목은 근거(`basis`)와 사람이 확인할 관찰점(`expect`)을 함께 적었다. 제외 요청된 갈등 대응 사례는 들어 있지 않다.

비교 도구:

```bash
python3 scripts/compare_prompts.py            # 20건 구조 비교 보고서
python3 scripts/compare_prompts.py --case C09 --show   # 프롬프트 전문
python3 scripts/compare_prompts.py --live --case C09 C10   # 실제 모델 응답 비교
```

구 프롬프트는 하드코딩하지 않고 `git show <revision>:choi_bot.py`에서 읽는다. 오프라인 보고서는 입력 크기, 최신 발언 중복 횟수, 규칙 포함 여부만 출력한다.

## 실제 모델 응답 비교 여부

**실시하지 않았다.** 사용자가 이번 단계에서 실제 API 호출을 하지 않기로 결정했다. 실제 Gemini 호출 0회, Discord 테스트 전송 0회다. Docker 컨테이너와 운영 서비스는 변경하지 않았다.

따라서 이 문서는 프롬프트와 입력 구성이 의도대로 바뀌었고 기존 계약이 깨지지 않았다는 것까지만 주장한다. **말투가 실제로 더 자연스러워졌는지, 장난 비중이 3:7에 가까워졌는지, 종료 표현 인식률이 올라갔는지는 검증되지 않았다.** LLM 출력은 비결정적이므로 특정 단어의 일치를 품질 기준으로 삼지도 않았다.

## 남아 있는 문제 및 Phase 2A 진행 조건

- `scripts/compare_prompts.py --live`로 20건 구/신 응답을 비교하고, 위 평가 항목 14개를 사람이 직접 채점해야 실제 개선을 확정할 수 있다. 이것이 Phase 1C의 남은 가장 큰 과제다.
- 응답 대상 구분, 침묵 임계값, 종료 오탐/미탐은 프롬프트 지시로만 처리한다. LLM 호출 전 필터나 종료 의도 분류기는 넣지 않았다. 실측 후 필요하면 별도 합의로 진행한다.
- 전역 공유 대화 하나라는 제약은 그대로다. 여러 채널에서 동시에 대화하면 여전히 같은 context를 공유한다.
- 대화 요청 입력이 약 4,700자로 이전(약 2,400자)의 약 두 배다. 토큰 비용과 지연이 늘 수 있으며 실측하지 않았다.
- 명령어 응답에 `00100`이 섞여 나오는지는 프롬프트 금지 지시로만 막는다. 런타임 필터는 추가하지 않았다.

Phase 2A는 Phase 1B에 적은 조건대로 진행한다. TXT 원본 inventory·백업, 출처/identity/time/type 계약, multiline parser, 중복·파싱 실패 보고, 재실행 가능한 migration dry-run 순서다. 실제 DB 전환 전에 SQLite 런타임·영속 디렉터리·backup-restore 검증이 필요하다. 이번에도 DB 구축이나 로그 변환은 실행하지 않았다.

## 작업 보존

작업 시작 시 있던 미커밋 변경은 유지했다. `BUILD_VERSION = "1.9.0"`은 작업 트리에 남기고 이번 commit에 포함하지 않는다. 키 검사 관련 `check_api_keys.sh`, `docs/API_KEY_CHECK.md`, `scripts/check_api_keys.py`, `tests/test_key_checker.py`와 `ini.env`도 변경하거나 commit에 넣지 않는다.
