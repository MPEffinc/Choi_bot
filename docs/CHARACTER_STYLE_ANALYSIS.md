## 2. 실제 말투의 핵심 특징

### 2.1 짧은 메시지와 짧은 대화는 다르다

원본 레코드 본문 기준 중앙값 6자, 평균 8.53자. 10자 이하 2,594건(75.0%), 40자 초과 45건(1.3%)이다. 공백·줄바꿈·Discord 마크업을 포함한 Python 문자열 길이이며 빈 본문 36건도 분모에 포함한다. 여러 줄 본문은 5건이다. 이것은 토큰 수나 의미 단위 발화 길이가 아니다.

“전 진실을” → “말했을뿐인데”처럼 문장을 여러 번 전송한다(E10). 설명·조율에서도 같은 분할이 나타난다(E12~13, E20~21). 따라서 '한 메시지가 짧으니 설명 자체를 싫어한다'는 해석은 맞지 않는다. 봇에서는 이러한 호흡을 짧은 절과 자연스러운 문장으로 표현할 수 있지만, 사람의 전송 횟수까지 그대로 복제할 필요는 없다.

### 2.2 평범한 수용과 확인이 바탕이다

본문 전체가 `?`인 기록 43건, `ㅖ` 23건, `에?` 22건, `ㅇㅇ` 19건, `예` 18건, `ㅇㅎ` 6건이다. E02의 ㅇㅋ, E05의 다음주?, E20의 아/ㅇㅋ처럼 내용 확인 후 끝내는 반응도 중요하다. `?`나 `에?`만으로 적대감·무지·비꼼을 확정할 수 없다.

### 2.3 반말·음슴체·존댓말·변형 어미를 섞는다

`없을꺼임`(E04), `이번주 금요일감`(E05) 같은 음슴체 외에 `있는뎅..`(E09), `곤란한 따름..`(E10), `그건 그냥 / 점프인데요?`(E12), `너무 감사하죠`(E13), `생각좀 해봅시더`(E21)가 공존한다. 존댓말은 진지함뿐 아니라 능청·감사·장난에도 쓰인다. '항상 음슴체', '항상 무덤덤'은 원본을 충분히 설명하지 못한다.

### 2.4 말장난·표기 변형은 상황을 강조한다

유아어 `최띠 때띠꼬얌?`(E06), 일본어풍 `카코이~`(E11), `곰엔나사이`(E16), 과장된 존칭 `문소사마님께서`(E18), 웃음 속 오타 `그말잉나ㅣ라`(E20)가 보인다. 의도적 변형과 실제 타이핑 실수의 경계는 확정하지 않는다. 독특한 표현을 매 문장 강제하면 오히려 평범한 수용·정보 전달을 가린다.

웃음을 연속 전송하는 실제 사례도 있다(E06). 다만 봇의 반복 방지는 사용성 규칙으로 별개 유지할 수 있다. 실제 사용 빈도를 그대로 출력 확률로 바꾸는 것은 권하지 않는다.

## 5. 단체 채팅 참여 방식

- 직접 호출 없이도 공통 화제에 들어온다(E07). 그러므로 이름·멘션이 없다는 이유만으로 봇의 후속 참여를 모두 막으면 이런 동조를 놓친다.
- 설명 중 다른 참가자의 농담에 짧게 답하고 원래 상대를 다시 명시한다(E12). 한 메시지의 직전 화자를 곧바로 '현재 유일한 대화 상대'로 취급하면 잘못된다.
- 여러 주제가 끼어들어도 자신의 질문·일정 흐름을 유지한다(E05·E13·E21). 원문은 채널 ID가 없어 모든 끼어든 메시지가 같은 채널이었다고 확정할 수는 없다.
- 맞장구 자체가 완결된 기여일 수 있다(E02·E20). 매번 농담이나 되물음으로 대화를 연장할 필요는 없다.
- 특정 질문 뒤 답변이 없더라도 '알면서 무시' 사례로 코딩하지 않았다. 온라인 상태·음성·Reply·DM이 없어 의도적 침묵률을 계산할 수 없다.

`00100`은 인간 말투가 아니라 봇의 출력 제어다. 현재 코드 L424 부근은 응답 문자열에 `00100`이 있는지 확인하고, 프롬프트 L162~165는 맥락 부족을 그 코드로 표시한다. E07·E12는 직접 호출 없이도 이어질 수 있다는 후보 근거지만, LLM 호출 전 필터의 정확도나 침묵 임계값을 정해주지는 않는다. 향후 평가는 '직접 호출', '공유 화제의 짧은 후속 질문', '명시적으로 제3자에게 한 질문', '다중 주제', '불확실한 반응 대상'을 분리해야 한다. 이 문서에서 새로운 제어 규칙을 적용하지 않았다.

6. 현재 말투를 중시할지 전체 기간의 역할극 특성을 중시할지 후속 프롬프트 설계에서 결정할 필요가 있다. 전체 기간을 섞으면 과거 유행어가 남고, 최근에만 맞추면 과거의 다양한 행동 표본이 줄어든다. 어느 쪽이든 E24 같은 시기 근거를 보존한다.

### 검증 기록

- 통계는 날짜별 원본의 정확한 대상 username만 사용했다. 합본·백업·별도 계정·봇 발언은 합산하지 않았다.
- 주요 질적 주장에 E01~E13·E16~E24 원본 경로·행 번호·시각·화자를 연결했다. 인용은 원본에서 추출하여 메시지 경계를 보존했다.
- 통계는 명시된 문자열 규칙으로 계산했으며 상황별 확률이나 성격 점수를 만들지 않았다.
- 현재 프롬프트는 코드 L139~204, 출력 제어는 L424 부근과 직접 대조했다. 소스·프롬프트·로그·운영 설정을 수정하지 않았다.
- 원본 로그는 저장소에 추가하지 않는다. 문서의 상대 경로는 로컬 원본 추적용이며 원격 GitHub에서 로그 링크가 열리지 않을 수 있다.
