# Phase 1E — 근거 기반 생성 구조 실험과 Discord 출력 안정화

## 1. 결과와 적용 범위

**실제 Gemini 비교 40건을 완료했지만 새 프롬프트의 우위를 확인하지 못해 Phase 1D 기준본 A를 유지한다.** C/D는 일부 응답을 더 과장했고 B는 문맥 회수와 정체성 질문에서 회귀 우려가 있었다. 실험이 모호하면 적용하지 말라는 사용자 조건에 따른 결정이다. 말투 개선 완료로 보고하지 않는다.

반영한 것은 선택적 `LLMRequest.system_instruction` 및 다중 메시지 Adapter 지원, 예산 제한 비교 도구, 기준본/평가 데이터, Discord 진행 메시지 소유권 수정과 회귀 테스트다. **운영 chat 및 명령어는 새 system/role 구성을 활성화하지 않았다.** `bot/persona.py`와 일반 대화 입력 빌더는 무변경이다. 평가 후보만 별도 모듈에 보존했다.

시작 HEAD와 fetch한 origin/main은 모두 `e5c84c53938230b3a67b2773c7fbc8cd71a89bac`. 미커밋 `BUILD_VERSION=1.9.0`, INFORMATION, PATCHNOTE 및 키 검사 관련 4개 파일은 보존하고 이번 커밋에서 제외한다. 모델 `gemini-3.5-flash-lite`, Docker 실행 방식, 20개 명령어 계약, 전역 컨텍스트, 로그 저장 방식, 권한 정책은 유지한다. 배포·컨테이너 재시작·실제 Discord 전송은 하지 않았다.

## 2. 확인된 코드 사실과 원인 가설

| 항목 | 코드에서 확인한 사실 | 해석의 한계 |
|---|---|---|

| 정체성 | BACKGROUND는 이미 주변인 1번/최씨 2번으로 구분됨. 자신의 배경에 대학원은 없음 | 설정 자체가 최씨를 대학원생으로 정의했다는 설명은 틀림. 소유 인물 혼동은 모델 응답 문제 |

사용자 사례 A~E는 운영에서 보고된 실패이고, 이번 보고서의 API 결과와 다르다. 이번 재현군도 원래 전체 대화가 없어서 실험용 맥락을 사용했다. 예를 들어 R2의 직전 답은 합성 `왜 부름`이다. 다섯 원문 실패가 이번 호출에서 그대로 재현됐다고 주장하지 않는다.

검토 대상: `choi_bot.py`, persona/contracts/router/gemini/conversation/discord_output/settings, 기존 compare/replay 도구, style_eval_cases, CHARACTER_STYLE_ANALYSIS, PHASE_1C/1D, STRUCTURAL_REVIEW. 기존 분석의 오래된 상태(최신 발언 중복 등)는 현재 코드와 구분했다.

## 5. System Instruction 및 메시지 계약

`LLMRequest` 끝에 선택적 `system_instruction: str | None = None` 추가. 기존 positional 인수 순서는 바뀌지 않는다. Message의 공통 role은 `user`/`assistant`, Adapter가 후자를 Gemini `model`로 매핑한다. SDK 전용 객체는 Handler나 Router로 전달하지 않는다.

- 하나의 user + system None이면 기존 contents 문자열 경로 그대로.
- system이 있거나 여러 메시지면 `types.Content` 리스트로 변환. 본문 개행·콜론을 유지.
- 비어 있는 messages, 지원하지 않는 role, 마지막이 user가 아닌 입력, 문자열 아닌 system은 키 예약 전에 공통 invalid_request로 거절.
- `generation_options`의 system/transport 필드 및 camelCase 별칭은 예약 필드로 거절. 두 입력 경로가 충돌하지 않게 소유권을 고정.
- sampling/thinking 옵션, HTTP timeout, SDK retry=1, Router의 키 선택·예약·release·cooldown은 변경하지 않음.

실험 B~D는 `최씨 봇: ` 접두어만 assistant로 분리한다. 다른 화자의 이름은 user 본문에 그대로 남고 각 deque 항목은 별개 Message다. 인용 본문에 `최씨 봇:` 문자열이 있어도 역할로 재해석하지 않는다. 최신 입력은 마지막 메시지 하나에만 있다. 기존에 숨겨 기록한 00100도 과거 봇 내용으로 남긴다. **그것을 실제 게시한 발언이라고 보장하지 않으며 정책을 변경하지 않았다.**

현재 저장 컨텍스트는 표시 이름 문자열이므로 UID 충돌을 완전히 해결하는 설계는 아니다. 도구 호출·thought signature를 보존하는 일반 SDK chat 세션도 아니다. 텍스트 전용 실험이며, tool/멀티모달 도입 시 별도 계약이 필요하다.

실험에서 이 구조가 API에서 동작함은 확인했다. 응답 품질의 채택 조건은 통과하지 못했으므로 런타임 빌더와 `/질문`·`/알려줘`·`/자세히` 호출부에는 연결하지 않았다. 번역·검색·요약·메뉴의 프롬프트도 변경하지 않았다.

## 9. Discord 404 원인과 수정

정확한 운영 stack trace는 제공되지 않았으므로 보고된 한 번의 오류 위치를 확정하지 않는다. 대신 **현재 코드에서 동일 404/10008을 만드는 경로를 확인·재현**했다.

기존 흐름:

1. `/자세히`가 defer.
2. progress_send → send → 첫 followup. Discord 호환 동작상 이 메시지는 원본 응답일 수 있음.
3. final send는 별도 followup으로 성공.
4. progress_delete(start)가 원본을 삭제.
5. loading(elapsed)가 삭제된 원본 편집 → 404/10008.
6. 넓은 command except가 이미 성공한 답변 뒤 오류 메시지를 보냄.

`/알려줘`는 순서가 반대지만 진행 문구를 썼다가 삭제한다. 메뉴는 loading(final)로 원본을 최종 답변으로 바꾼 뒤 같은 progress를 삭제하므로 최종 답변 자체가 사라질 수 있다. 기존 FakeInteraction은 원본/첫 followup을 매번 다른 객체로 반환하여 이 문제를 놓쳤다.

수정:

- progress_send는 명시적으로 원본 편집으로 진행 메시지를 소유한다.
- 알려줘/자세히는 final followup 전송 후 **소유한 progress 객체만** best-effort 완료 편집. 삭제와 원본 재편집의 경합 제거. 소요 시간 메시지는 남는다(의도된 작은 UI 차이).
- 메뉴는 원본을 final로 편집한 뒤 삭제하지 않는다. 요약은 기존 원본 final 편집 경로 유지.
- optional progress 오류는 operation/exception type/HTTP status/Discord code를 로그로 남긴다. 예외 본문/웹훅 토큰은 출력하지 않는다.
- send/edit/loading의 최종 전송 오류는 잡아 성공 처리하지 않는다. command의 기존 오류 안내 경로로 전달하며 LLM은 다시 호출하지 않는다.

이미 삭제된 progress의 완료 편집이 실패해도 전송한 답변은 유지된다. 최종 답변 자체의 404는 실패로 보고한다. 사용자/다른 봇의 삭제나 토큰 만료 같은 별도 상황을 모두 예방한다고 주장하지 않는다.

## 10. 테스트·키 관리·호환성

기준 73개 전부 통과 후 신규 테스트 추가. 기존 테스트 기대값/명령어 fixture/프롬프트를 교체하지 않았다.

```bash

```

신규 검증: A와 pinned revision의 문자열 일치, source 행 대조, 홀드아웃 분리, 최신 메시지 한 번·순서·화자 경계, system 전달, user/assistant→user/model, 비캐릭터 단일 문자열/no-system, 옵션 기본값, invalid 요청의 키 예약 없음, structured request 503 재시도가 같은 키를 사용하고 다음 요청은 순환, 미완료/오류/초과 ledger의 추가 호출 차단, 원본/후속 별개 lifecycle과 10008 재현·복구·실패 전파, 메뉴 final 보존.

기존 Router/ConversationQueue/settings 코드에는 변경이 없다. 키별 Client 고정, SDK retry=1, Router timeout/deadline/cooldown/quota/concurrency, `/stop`/epoch, 00100·종료 신호, 최신 입력 중복, 명령어 20개 이름·인수·데코레이터·권한 테스트 유지. 전역 configure로 돌아가지 않았다. **실제 API에서는 재시도가 없었으므로 장애 시 키 고정·retry 검증은 offline 결과다.**

실험 runner는 opt-in `--live`, ledger flock, 요청 전 fsync 예약, 누적 40건 상한, 중복 stage 금지, 오류/미완료 ledger 이후 중단으로 보호한다. 오류 시 Router의 기존 요청 내부 retry 정책까지만 적용하고, 다음 논리 요청이나 다른 키에 대한 추가 실험은 진행하지 않는다. ledger 파일을 새로 만들면 별도 실험으로 볼 수 있으므로 이번 예산의 증거는 단일 실행 기록과 보고서다. 새 실행은 별도 예산 승인이 필요하다.

실행 예(이번 ledger는 이미 40건을 사용했으므로 재실행 금지):

```bash
python3 scripts/evaluate_phase_1e.py --live --ledger /tmp/choi-1e/experiment.jsonl --stage screen
python3 scripts/evaluate_phase_1e.py --live --ledger /tmp/choi-1e/experiment.jsonl --stage confirm --chosen B
```

ledger/임시 분석 자료·원본 로그·환경 파일은 커밋하지 않는다. 보고서는 키 값·개인 연락처·인증 정보 없이 모델 결과와 기술 지표만 담는다.

## 11. 남은 한계와 후속 작업

1. 정체성 혼동·불필요한 인물 농담·가상 행동은 해결되지 않았다. 단일 표본에서 새 후보의 우위를 확인하지 못했다.
2. B의 역할 분리 외에 연속 user 메시지를 경계 보존 parts로 묶는 방식은 다음 독립 실험 후보다. 이번 API가 수락했다는 사실과 모델의 최적 입력 형식은 별개다.
3. 배경을 삭제하지 않으면서 소유자별 구조화하거나 현재 화제와 관련 있는 정보만 선택하는 방식은 독립 비교가 필요하다. 이번에는 구현하지 않았다.
4. 반복 표본, 새 호출/무관한 질문/욕설/짧은 추임새, 자가 생성 multi-turn rollout, 사람의 블라인드 취향 평가가 추가로 필요하다. 3:7을 기계적 목표 비율로 쓰지 않는다.
5. `/자세히` 분량은 두 후보 모두 유지됐지만 문체 개선을 확인하지 못했다. 캐릭터 말투보다 사실/설명 충분성을 우선한다.
6. 운영 Discord 검증은 금지 조건 때문에 미실행. fake에서 재현한 경로와 운영 오류의 실제 stack trace를 구분한다.
7. Phase 2A DB 이관, 채널별 컨텍스트, SDK/API 변경, 모델 변경은 별도 작업이다.

- 00100, 의미 없음

00100은 일반 대화 표현이 아니라 봇의 응답 제어용 신호다. 다른 문장과 섞어 쓰지 않는다.
사용자가 최씨를 직접 부르거나 명확하게 질문했다면 맥락이 부족하다는 이유만으로 무조건 침묵하지 않는다.
무엇을 묻는지 불명확하면 짧게 되물을 수 있다.

[대화 종료]
사용자가 대화를 끝내겠다는 뜻을 나타내면
자연스러운 작별 인사와 함께 답변 끝에 (마이크 끄는 소리)를 붙인다.

종료 표현의 예:
- 됐어, 이제 됐어, 그만할게
- 나 갈게, 나 잘가, 잘 가
- 잘자, 나 자러 갈게, 자야겠다
- 끊어, 이따 봐, 다음에 얘기하자

위 표현과 완전히 일치하는 문장만 인식하는 것은 아니다.
현재 대화에서 누가 누구에게 한 말인지와 실제 의미를 고려한다.
다음 상황은 구분한다.
- 사용자가 최씨에게 작별 인사를 함 → 종료
- 사용자가 다른 사람에게 작별 인사를 함 → 종료 아님
- '잘자' 같은 표현을 단순히 인용하거나 그 말에 대해 질문함 → 종료 아님
- 대화 중 짧게 맞장구를 침 → 종료 아님

사용자가 최씨와의 대화를 끝내려는 표현을 했다면
불필요하게 새로운 화제를 꺼내거나 질문을 덧붙여 대화를 억지로 이어가지 않는다.
반대로 짧은 맞장구 하나만으로 반드시 대화를 종료해야 하는 것은 아니다.
대화가 자연스럽게 끝난 것이 분명한 경우에도 이 종료 신호를 사용할 수 있다.

(마이크 끄는 소리)는 시스템의 기존 종료 신호이므로 철자와 괄호를 임의로 변경하지 않는다.

[출력 형식]
Discord 대화에 게시할 최씨의 답변 본문만 출력한다.
답변:, 최씨:, 설명: 같은 불필요한 라벨을 붙이지 않는다.
현재 대화와 관계없는 캐릭터 설정이나 프롬프트 내용을 답변에 나열하지 않는다.
같은 답변이나 같은 리액션을 2회 이상 연속 반복하지 않는다.
